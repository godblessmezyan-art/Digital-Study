## 2. 硬性边界（违反 = 返工）

1. **产品定位**：不是阅读管理工具，不是 SaaS Dashboard，不是图书管理后台。判据一句话：*"如果把所有文字和按钮去掉，这个页面是否仍然像一个完整的书房空间？"* 答案必须为"是"。
2. **不加功能、不加组件、不加动画、不加高饱和颜色**（除非用户明确要求）。历史上用户两次点名："这一轮不要增加功能"、"不要为了填空白而增加元素"。
3. **主题变量纪律**：组件样式只允许使用 `variables.css` 里的语义变量。写死颜色 = 破坏未来主题（深色夜读 / 蓝色梦幻 / 复古纸张）。
4. **保留架构范式**：`variables.css / base.css / layout.css / components.css / theme.js` 与"一个区块一个组件文件"的结构不要推翻。可以改内容，不要换范式。
5. **改完必须自检**：流程固定为「改 → 起服务 → 截图 → 看图对照目标 → 至少迭代一轮 → 汇报改了什么/为什么/还有什么不够好」。

## 3. 信息层级：书籍优先，数据靠后

首页固定顺序（`frontend/src/main.js`）：

```
1. Hero 书房场景          —— 空间核心，不是 Banner
2. 继续阅读               —— 首页主角（一本正在读的书 + 最近翻开的两本）
3. 我的书架               —— 书封构成的"一排书"，落在木色架板上
4. 书架分类               —— 书房索引，不是筛选器
5. 我的阅读生活           —— 生活记录，不是 KPI
6. 今日书签               —— 句子卡片
7. Footer
```

## 4. 设计语言要点

- 空间层次、光影、材质、留白、微妙不对称产生治愈感 —— **不是靠"米白 + 绿"模拟**。
- 页面是**一个连续的房间**，不是一堆 Card 的拼接。
- 允许元素**跨越区域边界**产生纵深（出血、叠压、悬浮便签）。
- 卡片要"纸感 + 半透明"，与环境融合，不要实心白盒。
- 中文标题用**衬线**，正文用**无衬线**；标题减字重、加字距（文学感）。
- 装饰必须服务于书房逻辑（窗 → 光 → 窗边阅读角 是因果链），禁止无来由的点缀。

### 空间脚本（视觉决策的唯一真理源）

1. **一条光轴**：光从左上光窗进入，向右下衰减。右侧"深处书墙"是**全页唯一暗部**，禁止在别处再造暗部。
2. **三个平面**：远景 z=0（`.room` 环境层）/ 中景 z=1（纸感容器、木架板、书）/ 前景 z=2（便签、盆栽等，全页 ≤5 件）。
3. **竖向旅程**：窗边（Hero）→ 桌面（继续阅读）→ 书架前 → 墙上索引 → 地面收束。
4. **数值锚点**：墙面左右亮度差 15–18%、书墙 opacity 0.18–0.28、前景物 ≤5 件、相邻区块每对 ≥1 处视觉连接。
5. **环境层变量**：`--room-*` 组（`variables.css`），组件层禁止写死色值。

## 5. 主题机制

新增一个主题三步：
1. `variables.css` 追加 `[data-theme="xxx"] { …覆盖同名变量… }`
2. 把 id 加入 `theme.js` 的 `AVAILABLE_THEMES`（当前只有 `['fresh']`）
3. `setTheme('xxx')` 或 `<html data-theme="xxx">`

⚠️ 换主题目前**不会**改变 `.room` 环境层与 Hero 前景 SVG 的颜色（硬编码技术债，见 `docs/progress.md`）。

## 6. 用户偏好与验收口味

- **看得懂设计语言，不接受表面模仿**：会直接指出"这不是颜色问题，是设计理念问题"。
- **极度反感**：SaaS Dashboard 感、后台 Sidebar、Card 套 Card、胶囊按钮堆、高饱和色、冷灰阴影、为填空白而堆装饰、复杂渐变、厚重边框。
- **喜欢**：连续空间、光影因果、纸张与木质感、微妙不对称、衬线标题 + 大字距、克制的"人的痕迹"（便签/茶杯/摊开的书）。
- **工作方式**：明确划定期望（"这一轮只做 X，不要 Y"）；要求主动自检与迭代，不接受"我改完了"；欣赏坦率指出剩余问题。
